# FR-017: Expose Quality Signals To The Observability Backend

- **Status:** Active
- **Traces to:** [US-21: system operator](https://github.com/Team8TemporaryName/Team8DebuggingGym/issues/92), [`QR-05`](../../quality-requirements/qr/QR-05.md), [`DEC-023`](../../decisions.md#dec-023)
- **Containers:** `webapp`

## Behavior

The product shall expose a quality signal for each runtime quality requirement, scoped to its environment, to the observability backend.

The product shall emit a structured log line for every HTTP request carrying `request_id`, `route`, `outcome`, and `duration_ms`, which the diagnosability requirement's test reads.

The product shall emit the signals only when observability is enabled.

## Acceptance Criteria

### AC-01

Given an HTTP request reaches the product, when the request completes, then the product emits a structured log line carrying `request_id`, `route`, `outcome`, and `duration_ms`.

### AC-02

Given observability is enabled, when a request completes, then the product exports the signal to the observability backend for the request's environment scope.

### AC-03

Given observability is disabled, when a request completes, then the product emits no signal.

### AC-04

Given a request fails, when the request completes, then the log line's `outcome` records the failure label (`client_error` or `server_error`) and the `request_id` can find the line in the observability backend.
