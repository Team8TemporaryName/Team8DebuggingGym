# FR-016: Privacy-Conscious Product Analytics

- **Status:** Active
- **Traces to:** [`US-20`](https://github.com/Team8TemporaryName/Team8DebuggingGym/issues/91), [`ADR-005`](../../architecture/adr/ADR-005.md)
- **Containers:** `webapp`, `analytics`

## Behavior

The product shall record core learner interactions to support measurement of exercise usage and successful verification.

The product shall emit the documented analytics events with their required properties and a valid source: `web`, `usability-test`, or `smoke`.

The product shall assign each learner a random opaque identifier and reuse it across visits without deriving it from personal information.

Analytics delivery shall be best-effort and shall not interrupt exercise generation, execution, or verification.

The product shall not send source code, exercise solutions, credentials, names, email addresses, or other directly identifying personal information to the analytics provider.

Staging and production analytics data shall use separate projects or scopes and distinct credentials.

## Acceptance Criteria

### AC-01

Given a learner visits the application, when the application records `app_opened`, then the event includes a meaningful `first_visit` boolean and a valid `source`.

### AC-02

Given a learner generates or starts an exercise, when the corresponding action succeeds, then the product records `exercise_generated` or `exercise_started` with the required `exercise_id` and `kind` properties.

### AC-03

Given a learner runs verification, when the verification finishes, then the product records `verification_run` with the exercise identifier and pass result.

### AC-04

Given verification succeeds, when the exercise is completed, then the product records `exercise_completed` with the required exercise properties.

### AC-05

Given a learner visits the application more than once, when analytics events are emitted, then the same valid opaque learner identifier is reused.

### AC-06

Given analytics credentials are missing or the provider is unavailable, when a learner uses the application, then the core application task continues without interruption.

### AC-07

Given an analytics event is emitted, when its payload is validated, then it contains the documented required properties and a valid source.

### AC-08

Given staging and production analytics are configured, when events are sent, then each environment uses its own project or scope and credentials, and smoke traffic is excluded from product metrics.
