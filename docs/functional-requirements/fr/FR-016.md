# FR-016: Record Analytics Events For The Core Task

- **Status:** Active
- **Traces to:** [US-20: product analyst](https://github.com/Team8TemporaryName/Team8DebuggingGym/issues/91), [`DEC-023`](../../decisions.md#dec-023)
- **Containers:** `webapp`

## Behavior

The product shall record an analytics event for each step of the core task, with the fields `docs/analytics.md` records, and send each event to the analytics backend.

The product shall tag each event with a `source` field of `web`, `usability-test`, or `smoke`, and shall send a staging test event tagged `source=smoke`.

The product shall not collect personal data in any event; a learner is identified by an opaque identifier.

## Acceptance Criteria

### AC-01

Given a learner opens the app, when the app loads the exercise list, then the product records an `app_opened` event with a `source` field.

### AC-02

Given a learner opens an exercise to solve it, when the exercise is retrieved, then the product records an `exercise_started` event carrying the exercise identifier and kind.

### AC-03

Given a learner submits a fix for verification, when the verify request completes, then the product records a `verification_run` event with the pass/fail `outcome`.

### AC-04

Given a learner's fix passes the harness, when the verify completes, then the product records an `exercise_completed` event.

### AC-05

Given an event is recorded, when a learner is identified, then the identifier is opaque and not derived from personal data, and no event carries a personal field.
