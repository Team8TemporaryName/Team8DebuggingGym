# QR-02: Testable Generator And Frontend From A Clean Checkout

A developer can run the checks that cover the generator and the browser exercise flow from a clean checkout, and a broken change fails them.

- **Status:** Active
- **Characteristic:** Maintainability
- **Sub-characteristic:** Testability
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

A developer on the Debugging Gym team, after the course, who has cloned the repository on a fresh machine.

### Stimulus

The developer runs the repository's check command for the product code with no prior environment, following the setup page.

### Environment

A clean checkout with the Python and Node.js toolchains from [`docs/setup.md`](../../setup.md) installed, and no cached build artifacts.

### Artifact

The critical modules are the browser frontend entry point [`app/static/app.js`](../../../app/static/app.js), which drives the browser exercise flow, and the generator module [`app/generator.py`](../../../app/generator.py), which produces every exercise. The suite also tests the harness runner [`app/harness_runner.py`](../../../app/harness_runner.py).

### Response

The test command shall exercise the generator contract, the harness runner's pass/fail behavior, and the browser frontend's problem-selection and verification-result flow. It shall fail when a tested behavior breaks, without the developer opening a story or requirement.

### Response Measure

From a clean checkout, `python -m pytest tests/ -q` completes in under a minute and passes. A broken change to `app/generator.py` or `app/static/app.js` makes at least one test fail.

The `Maintainability` / `Testability` pair is `High` business importance because the instructors are stakeholders and the course is part of the business, so the product's checks must survive the term.

## Critical Modules

The critical modules this requirement names are the frontend entry point [`app/static/app.js`](../../../app/static/app.js) and the generator module [`app/generator.py`](../../../app/generator.py). Both are covered by the clean-checkout test suite. The harness runner has additional tests because it supplies the generator's verification behavior.

## QRT-02

The product CI runs the full automated suite from a clean checkout and detects regressions in the named critical modules.

- **Status:** Active
- **Level:** CI
- **Runs at:** `.github/workflows/product-ci.yml`, step `Run automated tests for Python and browser frontend`.
- **Command:** `python -m pytest tests/ -q`

### Procedure

1. Open the latest Product code CI run triggered by a pull request or a push to `main`.
2. Confirm the workflow starts from a fresh checkout, installs the documented development dependencies, and runs the command above.
3. Confirm the suite includes tests for `app/static/app.js`, `app/generator.py`, and the harness runner.

**Pass when:** The complete test suite exits successfully from a clean checkout, and it includes automated coverage for the browser frontend and generator named as critical modules in this requirement.
