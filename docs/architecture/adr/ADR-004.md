# ADR-004: Keep Local Harness Feedback Separate from Official Verification

- **Status:** Accepted
- **Created:** 2026-10-31
- **Updated:** 2026-10-31
- **Containers:** `vscode-extension`, `webapp`, `debug-runtime`
- **Addresses:** [`FR-003`](../../functional-requirements/fr/FR-003.md), [`FR-009`](../../functional-requirements/fr/FR-009.md)
- **Decision:** [`DEC-017`](../../decisions.md#dec-017)

## Context

The customer requires the learner to inspect, edit, and run the local harness. However, allowing a learner to modify the only test used for official verification would make the reported result untrustworthy.

The product therefore needs to preserve local experimentation while ensuring that the official verdict remains under server control.

## Considered Options

- **Use the local harness as the official verifier.** This makes local feedback simple but allows a learner's changes to the harness to influence the result.
- **Provide an editable local harness and separate server-side verification tests.** This permits local experimentation while keeping official verification independent of learner changes.

## Decision Outcome

Chosen option: provide the learner with an editable local harness and run the authoritative verification tests on the server. The local harness may be restored to the original version supplied with the exercise, but modifications to the local file do not determine the official verdict.

## Consequences

- **Trustworthiness:** the official result remains based on server-controlled tests.
- **Learning:** learners can inspect, modify, and run the visible harness locally.
- **Implementation cost:** local feedback and official verification must be kept separate, and their results must be communicated clearly.
